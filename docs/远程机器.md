# 远程机器

用同一套界面管理两台电脑上的 opencode。当前支持一台本机加任意台局域网机器。

## Windows 10 一侧

1. 在 Windows 上安装 opencode，确认命令行能执行 opencode。
2. 设置固定密码并启动服务，允许局域网访问：

```
set OPENCODE_SERVER_PASSWORD=你自己的密码
opencode serve --hostname 0.0.0.0 --port 4096
```

3. 第一次启动时 Windows 防火墙会弹窗，选择允许专用网络访问。没有弹窗就去 Windows 安全中心放行 4096 端口。
4. 把网络设为专用网络：设置 > 网络和 Internet > 属性 > 网络配置文件改成专用。
5. 用 ipconfig 查到这台机器的局域网地址，例如 192.168.0.50。

## 管理端一侧

1. 在本项目根目录新建 .machines.json，内容照着 .machines.example.json 写，把 url 与 password 换成 Windows 那台机器的。

```
{
  "machines": [
    { "id": "win10", "name": "Win10", "url": "http://192.168.0.50:4096", "password": "你的密码" }
  ]
}
```

2. 重启本项目。
3. 侧栏顶部会出现机器切换标签，点 Win10 就把整个界面切到那台机器。

.machines.json 含密码，已经在 .gitignore 里，不要提交。

## 远程模式下的变化

1. 项目目录是否存在不再用本机路径判断，直接采用远端返回的项目列表。
2. 会话头部的运行与打开按钮、右键菜单里的打开目录、在终端打开、复制启动命令都会隐藏，因为这些动作只对本机有意义。
3. 新建会话只能手输远端绝对路径或点最近项目，不能弹本机目录对话框。
4. 事件流按机器单独订阅，切换标签会整页重载一次。

## 安全

1. 只在家里或可信的局域网使用，HTTP 明文传输，密码只能挡住随手访问。
2. 不要把 4096 端口映射到公网；需要外网访问时用 Tailscale 之类的组网工具。
3. 更换密码后所有旧会话立即失效，需要在 .machines.json 里同步更新。

## 一键接入提示词

把下面整段复制到 Windows 10 机器上的 opencode 里执行，它会自己装好、放行端口、自测并输出连接信息。

```
目标：把这台 Windows 10 机器的 opencode 配置成可被局域网内另一台 Mac 管理。请自己执行并验证，不要让我手动操作。

1. 检查 opencode 是否可用：opencode --version。不可用就安装到最新版并再次验证。
2. 生成一个 20 位随机字母数字密码并记住，不要使用中文或符号。然后配置后台服务：
   opencode service set hostname 0.0.0.0
   opencode service set port 28894
   opencode service set password <刚才生成的密码>
   opencode service start
   如果这台机器的 opencode 没有 service 子命令，就改用前台常驻方案：写一个启动脚本，设置 OPENCODE_SERVER_PASSWORD，执行 opencode serve --hostname 0.0.0.0 --port 4096，并把脚本放到登录时自动运行，端口改用 4096。
3. 放行防火墙，只对专用网络开放：
   netsh advfirewall firewall add rule name="opencode-lan" dir=in action=allow protocol=TCP localport=<实际端口> profile=private
4. 确认监听：netstat -ano | findstr <实际端口>，必须看到 0.0.0.0 或本机局域网地址。
5. 取局域网 IPv4：ipconfig，排除 127.0.0.1、虚拟网卡与 VPN 地址，优先 192.168 或 10 开头的地址。
6. 本机自测，返回 200 才算通过：
   curl -u opencode:<密码> http://<IP>:<端口>/api/info
7. 按下面格式输出，不要省略：

计算机名：
地址：http://<IP>:<端口>
密码：<密码>
.machines.json 片段：
{"machines":[{"id":"win10","name":"Win10","url":"http://<IP>:<端口>","password":"<密码>"}]}

约束：不要把端口映射到公网，不要修改系统全局代理，不要把密码写进任何会提交到 git 的目录；最后确认服务由后台托管，关掉当前终端后仍然可访问。
```

## macOS 本地网络权限

macOS 15 之后，第三方程式访问局域网需要授权。表现是同一个地址 curl 能通，Python 与 Node 却报 No route to host。

1. 打开 系统设置 > 隐私与安全性 > 本地网络。
2. 给运行本项目的应用打开开关，通常是 opencode 或终端。
3. 列表里没有就先用终端跑一次 just_run.sh，等系统弹窗时允许，再重启服务。

## 本机访问远端的实现细节

macOS 的本地网络权限会拦住 Python 与 Node 的局域网连接，表现为 curl 能通、程序报 No route to host。远端请求统一改为调用系统 curl 子进程，事件流用 curl 长连接转发，避开了这个权限限制。
