# 远程机器

用同一套界面管理两台电脑上的 opencode。当前支持一台本机加任意台局域网机器。

## 本次结果

1. 计算机名：Win10-PC
2. 局域网地址：http://192.168.0.50:28894
3. 监听：0.0.0.0:28894，由 opencode service 托管。
4. 防火墙：规则 opencode-lan，仅专用网络，TCP 28894。
5. 网络位置：WLAN 已设为专用网络。

密码不写进文档，保存在用机本地；需要时用 opencode service get 查看。

## 步骤

1. 检查 opencode 版本，不可用就安装最新版。

```
opencode --version
```

2. 生成 20 位随机字母数字密码，并配置后台服务。执行 service set 时 opencode 可能自动重启服务，当前会话会短暂断线。

```
$bytes = New-Object byte[] 20
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
$chars = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789'
$pwd = -join ($bytes | ForEach-Object { $chars[$_ % 62] })
opencode service set hostname 0.0.0.0
opencode service set port 28894
opencode service set password $pwd
opencode service start
```

3. 只对专用网络放行防火墙。需要管理员权限。如果当前网络是公用，先把 WLAN 改成专用，否则专用规则不会生效。

```
Set-NetConnectionProfile -InterfaceAlias 'WLAN' -NetworkCategory Private
netsh advfirewall firewall add rule name="opencode-lan" dir=in action=allow protocol=TCP localport=28894 profile=private
```

4. 确认监听地址必须是 0.0.0.0 或局域网地址。

```
netstat -ano | findstr :28894
```

5. 取局域网 IPv4，排除 127.0.0.1、169.254、VMware、Hyper-V 与 VPN 地址。

```
ipconfig
```

6. 本机用局域网地址自测，正确密码返回 200，错误密码返回 401。

```
curl.exe -u opencode:密码 http://192.168.0.50:28894/api/info
```

7. Mac 端写入 .machines.json，地址使用 Windows 的局域网 IP，不要写 0.0.0.0。

```
{"machines":[{"id":"win10","name":"Win10","url":"http://192.168.0.50:28894","password":"密码"}]}
```



## 地址会变怎么办

开机自动连上的做法：Windows 上一次性固定端口与密码，Mac 上只记密码，IP 变了自动在局域网里找。

1. Windows 上固定端口和密码，只需做一次。opencode 重启后端口不再变。

```
opencode service set hostname 0.0.0.0
opencode service set port 28894
opencode service set password 你的固定密码
opencode service restart
```

2. Mac 的 .machines.json 只写机器编号、名字、密码。url 可以写旧地址，连不上会在局域网按密码自动查找，找到后记住。

```
{"machines":[{"id":"win10","name":"Win10","url":"http://192.168.0.102:28894","ports":[28894,4096],"password":"你的固定密码"}]}
```

3. 想加固定名字或备用地址就写进 urls。Tailscale 的 100 开头地址也可以写，换网络也能连。

```
{"machines":[{"id":"win10","name":"Win10","url":"http://192.168.0.102:28894","urls":["http://192.168.0.102:28894","http://win10-pc.local:28894","http://100.88.0.5:28894"],"ports":[28894,4096],"password":"你的固定密码"}]}
```

4. 端口扫描只查 ports 里的端口加 4096，所以 Windows 那边端口一定要固定，否则找不回来。

## 连不上时的表现

1. 远端连不上只影响那台机器的页面，本机数据照常显示，顶部标签可以直接切回本机。
2. 错误页有自动查找按钮，会把整个局域网按密码找一遍，换 IP、换端口都能自己找回来。
3. 配置里已经不存在的机器编号会自动退回本机，不会卡在错误页。
4. 所有地址都失败时提示里会列出每个地址的真实失败原因。
5. 找到的地址存在项目根目录的 .machines.state.json，下次启动先试它。

## 远程模式下的变化

1. 项目目录是否存在不再用本机路径判断，直接采用远端返回的项目列表。
2. 会话头部的运行与打开按钮、右键菜单里的打开目录、在终端打开、复制启动命令都会隐藏，因为这些动作只对本机有意义。
3. 新建会话只能手输远端绝对路径或点最近项目，不能弹本机目录对话框。
4. 事件流按机器单独订阅，切换标签会整页重载一次。

## 管理端

1. 在本项目根目录新建 .machines.json，格式见 .machines.example.json。
2. 重启本项目，侧栏顶部出现机器标签，点一下切换。
3. .machines.json 含密码，已在 .gitignore 里，不要提交。

## 安全

1. 只在家里或可信局域网使用，HTTP 明文传输，密码只能挡住随手访问。
2. 不要把端口映射到公网；外网访问用 Tailscale 之类的组网工具。
3. 更换密码后所有旧会话立即失效，需要同步更新 .machines.json。

## macOS 本地网络权限

macOS 15 之后，第三方程式访问局域网需要授权。表现是同一个地址 curl 能通，Python 与 Node 却报 No route to host。

1. 打开 系统设置 > 隐私与安全性 > 本地网络。
2. 给运行本项目的应用打开开关，通常是 opencode 或终端。
3. 列表里没有就先用终端跑一次 just_run.sh，等系统弹窗时允许，再重启服务。

## 本机访问远端的实现细节

macOS 的本地网络权限会拦住 Python 与 Node 的局域网连接。远端请求统一改为调用系统 curl 子进程，事件流用 curl 长连接转发，避开了这个权限限制。
