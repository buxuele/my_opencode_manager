# 接口与数据说明

本文记录本项目读取的 opencode v2 API、字段来源与实现中的约束，便于后续升级 opencode 后核对。

## 服务发现

1. 服务信息文件：`~/.local/state/opencode/service.json`。
2. 关键字段：url 为服务地址，password 为认证密码，version 为 opencode 版本，pid 为服务进程号。
3. 认证方式：HTTP Basic，用户名 opencode，密码取 password 字段。
4. 请求方为本地进程，httpx 必须设置 trust_env=False，否则会被 Clash 的 SOCKS 环境变量劫持。
5. 启动脚本先调用 ensure_opencode.py 读取 service.json 并请求 /api/info；未就绪时执行 opencode service start，最多等 30 秒，失败则退出。
6. 测试自动启动时可设 OCM_OPENCODE_STATE 指向临时状态目录、OCM_OPENCODE_BIN 指向替身命令，避免影响真实服务。

## 读取接口

1. `GET /api/project` 返回项目数组，字段含 id、canonical、time.created、time.updated、time.active、sandboxes；本项目后端额外补 exists，表示本地目录是否仍存在。
2. `GET /api/session?limit=1000` 返回对象，data 为会话数组，cursor 为翻页游标。
3. 会话字段：id、projectID、parentID、agent、model、cost、tokens、time.created、time.updated、title、location；结束过的会话还带 outcome 与 time.idle，outcome 取值 succeeded、failed、interrupted。
4. `GET /api/session/active` 返回对象，data 的键是正在运行的会话 ID，值为 type=running。
5. `GET /api/session/{id}` 返回对象，data 为会话详情。详情含 outcome 与 time.idle，outcome 取值 succeeded、failed、interrupted，time.idle 是本轮结束时间，两者是会话状态的唯一依据。
6. `GET /api/session/{id}/message?limit=200&order=asc` 返回 data 与 cursor。cursor.next 存在时继续翻页，翻页请求只带 cursor，不能再带 order。
7. 消息字段：id、type、time、text、files、agents、content。type 常见值有 user、assistant、compaction、shell、system、synthetic、idle、model-switched、agent-switched。
8. assistant 的 content 是数组，元素 type 为 text、reasoning、tool。tool 的 state 含 status、input、content。
9. `GET /api/session/{id}/inbox` 返回还没进入消息列表的排队输入，data 数组元素含 id、time、type=user、payload.text、delivery。
10. `GET /api/model?location[directory]=...` 返回可用模型，data 元素含 modelID、providerID、name、variants、enabled。
11. `GET /api/agent?location[directory]=...` 返回 agent，data 元素含 id、name、mode、hidden、description。
12. `GET /api/session/{id}/permission` 返回待授权请求，元素含 id、action、resources、message。
13. `GET /api/session/{id}/form` 返回待填表单，元素含 id、title、fields；字段类型有 string、number、integer、boolean、multiselect、external。
14. `GET /api/experimental/session/stats?timezone=Asia/Shanghai&tools=summary` 返回活跃天数、连续天数与近 14 天活动，同时带用量与成本字段，本项目只使用活跃数据。

## 写接口

1. `PATCH /api/session/{id}`，请求体可含 title，成功返回 204，没有响应体。
2. `DELETE /api/session/{id}`，成功返回 204。
3. `POST /api/session`，请求体为 location.directory 加可选 title，返回新建会话，本项目用于侧栏与会话页的新建入口。
4. `POST /api/session/{id}/prompt`，请求体至少包含 text；delivery=queue 表示排队等待当前回合结束，不传时默认 steer 直接插话。
5. `POST /api/session/{id}/interrupt`，中断当前执行，空闲时返回 interrupted=false。
6. `DELETE /api/session/{id}/inbox/{inboxID}`，取消还没投递的排队消息，不可取消时也是 204。
7. `POST /api/session/{id}/model`，请求体 `{model:{id,providerID}}`，成功返回 204。
8. `POST /api/session/{id}/agent`，请求体 `{agent:id}`，成功返回 204。
9. `POST /api/session/{id}/permission/{requestID}/reply`，请求体 `{decision: once|always|reject}`，成功返回 204。
10. `POST /api/session/{id}/form/{formID}/reply`，请求体为 `{answer:{字段名:值}}`；`DELETE /api/session/{id}/form/{formID}` 取消表单。
11. `POST /api/session/{id}/compact`，请求体可为空对象，压缩排入队列。
12. `POST /api/session/{id}/revert/stage`，请求体 `{messageID,files:false}` 标记回退边界；再调用 `POST /api/session/{id}/revert/commit` 才会真正删除该消息及其之后的回复。
13. `PATCH /api/project/{id}`，请求体可含 name、canonical、icon、commands，本项目只使用 name。
14. `POST /api/run`，请求体为 path，按当前系统检查 just_run.bat 或 just_run.sh 后打开终端执行，并把窗口标题设为「项目名 · 脚本名」；缺少脚本返回 404。终端与窗口操作由 platform_ops.py 的适配类实现。
15. `POST /api/pick-folder`，请求体可含 path 作为初始目录，调用 Windows 文件夹对话框、macOS choose folder 或 Linux 目录选择框，返回 path 与 cancelled；取消时 path 为 null。
16. `POST /api/reveal`，请求体为 path 与 target，target 为 terminal 时在该目录打开终端，target 为 project 时按系统打开项目：Windows 直接打开项目目录，macOS 在访达打开上级目录并选中项目，方便马上开终端；select 为真时仍可在上级目录选中该文件夹。
17. `GET /api/platform` 返回当前系统的显示信息：name、label、script、folderLabel、shortcut，前端只用它决定快捷键符号与文件夹称呼。
18. `GET /api/preferences` 返回 initialized、version、settings、pinnedProjects、updated；文件不存在时 initialized 为 false，settings 为默认值。
19. `PUT /api/preferences` 接收 settings 与 pinnedProjects，按字段合并后原子写入偏好文件；未知字段返回 400。

## 命令与授权

1. `GET /api/command`，返回当前目录已注册的命令，元素含 name 与 description；本项目后端包装为 `GET /api/commands?directory=...`。
2. `POST /api/session/{id}/command`，请求体为 `{name,arguments,text}`，成功返回 204 并立即开始执行，不等待模型完成。
3. 输入框以 / 开头的文本按第一个空格拆成命令名与参数，走命令接口；未注册命令返回 404，文本退回输入框。
4. 待授权请求拉取后自动以 always 回复，不再停在卡片上；表单无法自动填写，仍需人工提交。

## 事件流

1. 地址：`GET /api/event`，响应类型 text/event-stream。
2. types 参数是 explode 数组，必须重复书写，例如 `types=session.created&types=session.deleted`。
3. 本项目订阅的事件：session.created、session.deleted、session.renamed、session.inbox.enqueued、session.inbox.delivered、session.inbox.cancelled、session.execution.started、session.execution.succeeded、session.execution.failed、session.execution.interrupted、session.step.ended、session.step.streamed、session.text.ended、session.model.selected、session.agent.selected、session.compaction.started、session.compaction.ended、session.compaction.failed、session.revert.staged、session.revert.cleared、session.revert.committed、permission.asked、permission.replied、form.created、form.replied、form.cancelled、project.updated。
4. server.connected 与 session.message.created 不在允许枚举内，不能放进 types。
5. 上游返回 Keep-Alive: timeout=5，空闲五秒会关闭。代理层需要自行重连并向浏览器补心跳，不能让浏览器感知上游断线。
6. `session.execution.started` 与 `session.execution.succeeded`、`session.execution.failed` 只表示一次执行开始或终止，`session.step.failed` 与 assistant 消息的 error 只表示单个步骤，三者都不能直接当成会话状态。

## 页面到接口的映射

1. 侧栏会话固定取最近 20 条；项目列表按会话数聚合，只保留会话数大于 0 且 exists 为真的项目。
2. 全部项目页只展示会话列表并按更新时间排序；项目页只保留项目路径、项目操作与会话列表，不再请求 stats。
3. 会话列表按游标分页拉取，每页 500 条，最多 20 页，再按项目与搜索词过滤，前端每页 30 条；归档不再出现在界面。
4. 会话页先取详情与最近 12 条消息立即显示，再用 cursor 补足 30 条，顶部按钮继续加载更早内容；渲染时只保留 user、assistant、compaction、shell、model-switched、agent-switched 六类，其余系统消息不展示。
5. 执行中投递的新消息带 delivery=steer，在下一个步骤边界进入当前上下文，气泡标注已插话；其他来源带 delivery=queue 的消息仍在队列里，显示排队中并可取消。
6. 刷新会话时先比对 time.updated，没有变化就不拉消息；有变化只取最新 12 条合并，执行中按流式事件强制取最新 6 条；合并时按消息签名复用未变化的对象，遇到断层只重取最近 80 条，不再全量重载。
7. 会话与项目地址写在 hash 上，刷新与前进后退按地址恢复；输入草稿按会话号存在 localStorage，切换或刷新后恢复。
8. 模型与 agent 列表按会话所在目录请求，切换后只影响后续回合；模型列表展示每百万 token 的输入输出价格。
9. 待授权与待填表单在输入框上方展示，事件 permission.asked 与 form.created 触发重新读取；侧栏会扫描最近 20 个会话与运行中会话，有待处理时显示待处理标记，每 30 秒复核一次。
10. 表单字段支持 when 条件，条件不满足时不显示也不提交。
11. 后台会话的完成标记只由会话列表里的 outcome 与 time.idle 生成：新的 idle 到达后等待 2.5 秒，期间没有新的执行才写入已完成、失败或已中断；执行事件与步骤事件不直接写标记，打开会话后清除。
12. 会话执行中的 step.ended 不再刷新整个会话列表；只在回合结束、生命周期事件与运行中每 60 秒刷新，减少大列表重复拉取。
13. 历史附件默认只保留文件名，点击时按单条消息接口取回原图；发送前附件支持选择、拖拽与粘贴。
14. 会话完成时用 Web Audio 合成轻提示音，偏好存在 ~/.config/opencode_manager/preferences.json，localStorage 的 ocm_settings 只做缓存；首次点击或按键时解锁音频上下文。
15. 会话头部的运行按钮调用 /api/run，在项目目录执行当前系统的启动脚本；没有脚本时不启动终端并提示。目录与终端操作全部走 platform_ops.py。
16. 置顶项目与设置共用同一份偏好：打开页面先读 GET /api/preferences，initialized 为 false 时把本地缓存 PUT 上去，之后每次修改延迟 250 毫秒合并写入，页面关闭前再用 keepalive 补一次。草稿仍按会话存在本机 localStorage，不跨设备同步。
17. 消息里的 error 只在它是最后一条助手消息且会话 outcome 为 failed 时显示执行失败；中间尝试显示本次尝试失败，步骤中断显示本步已中断，工具状态显示本步失败，避免把步骤状态当成会话状态。
