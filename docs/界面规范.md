# 界面规范

从本项目多轮返工里总结出来的通用规则。新页面、新组件动手前先过一遍，改完再对着检查一次。

1. 一屏只留必要信息。重复的标题、项目名、创建时间、状态描述，先删再加。
2. 同一状态只显示一处。执行中、连接状态、错误提示不能三处并存。
3. 层级靠缩进、字重与底色，不靠竖条、箭头和框线。装饰前先问：用户会因此多点或看清什么，说不出来就不加。
4. 列表行右侧只放一个事实列，数字与时间右对齐，多列必须共用一条右边缘。
5. 颜色只做三档：灰阶打底，品牌紫标识身份，红色只给危险操作。引入新颜色必须能说出用途，否则用灰。
6. 字号下限：正文 16 像素，界面 14 像素，附着信息 13 像素。任何文字对比度不低于 4.5 比 1。
7. 顶部只留一条栏，高度不超过 52 像素，不重复面包屑与页面标题，滚动时吸顶。
8. 交互只保留一种模型。点名字展开就用点击，不再加第二个指示器。移动端点击目标不小于 44 像素。
9. 空状态说人话，给下一步动作，不写与当前场景无关的提示。
10. 长内容先折叠：大段文本、长列表、长表单都要有折叠、分页或限高，大字符串不进受控输入框。
11. 按钮带中文标签，核心动作放右下或主位，破坏性动作必须二次确认。
12. 动效克制，不做循环动画；进度与耗时用真实数据，缺数据就显示空状态。

跨项目的完整打磨清单见 ~/.config/opencode/项目打磨清单.md，新项目开工前按它逐条对照。
