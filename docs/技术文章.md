# 我给 opencode 做了个网页驾驶舱

我每天要开十几个 opencode 会话。在终端里翻历史、记目录、找哪个窗口还在跑，翻着翻着就烦了。于是花几天时间，给自己写了个网页控制台。现在打开一个网址，项目、会话、模型、运行状态全在眼前。

## 它是什么

一个只跑在本机的网页。数据全部来自本机正在运行的 opencode 服务，不复制数据库，不落盘，也不往云端发一个字节。

启动就一条命令：

```
./just_run.sh
```

脚本会检查依赖、构建前端、探测端口，然后把页面打开。

## 技术选型

后端是 FastAPI，做两件事：代理 opencode 的接口，以及把事件流转发到浏览器。前端是 React 加 Vite，样式全部手写，没有引入组件库。没有数据库，没有登录，只监听 127.0.0.1。

之所以敢这么薄，是因为 opencode 本身已经把事情做完了，界面只需要把数据摆好、把操作递过去。多一层数据库，就多一份会过期的副本。

## 几个我觉得值的设计

1. 事件流优先。执行中的输出按增量推送，页面不整段重载；断线自动重连，回来接着刷。
2. 执行中还能插话。新消息按 steer 送进当前回合，在下一个步骤边界被读到，输入框不会被锁死。
3. 长文本折叠。一次贴十几万字，输入框不再硬扛，而是折成一个带字数的小块，想看再展开。
4. 数据不落地。所有读写都走 opencode 的公开接口，页面关掉，什么都不留。
5. 键盘与深链。⌘K 搜会话，地址栏能刷新、能前进后退，每个会话的草稿单独存。
6. 一些顺手的细节。打开按钮会在访达里定位项目文件夹并选中；运行按钮在终端执行项目的 just_run.sh，窗口标题带项目名；会话跑完有一声轻提示。

## 踩过的三个坑

第一个，访达的暴脾气。

一开始用系统的 open 命令打开上级目录，结果访达窗口不动，只把旧窗口提到前面，看着像打开了上上级。改成 AppleScript 之后又发现，select 会把前台交还给上一个应用，选中虽然生效，窗口却退到后面，只剩一片灰。最后的解法是在选中之后，再喊一次 activate 把访达叫到前面。

第二个，灰色配灰色。

我偏爱浅灰主题，做着做着发现侧栏的计数、时间、版本号几乎看不见。扫了一遍全站，发现最小的对比度只有 1.2 比 1，离能读还差得远。后来定了一条硬规矩：所有文字对比度不低于 4.5 比 1，灰底上的灰字一律加深。

第三个，MCP 越滚越多。

有次一启动页面，系统里冒出七八套 chrome-devtools 进程。查下来不是页面起的，是 opencode 按项目目录各实例化一套 MCP，一旦碰过某个目录就常驻不回收。页面每三十秒对最近二十个会话逐个查状态，等于把好几个目录同时点亮。把检查范围收窄到活跃会话之后，进程数稳住了。

## 适合谁

适合本机跑 opencode、经常在多个项目之间来回切的人。如果你一天只用一个会话，终端其实更顺手，这个项目帮不上什么忙。
